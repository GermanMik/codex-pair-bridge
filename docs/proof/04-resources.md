# ProofLoop 04: resource management

Acceptance: per-device calls queue for at most 30 seconds; configured `max_loaded_bytes` blocks cold loads when the CLI memory estimate for the candidate at its planned context plus loaded instances at their actual contexts and 10% headroom exceeds the configured budget. The bridge never unloads unrelated instances to make room. Queue/load/inference stages are visible in the local journal while running; load results report LM Studio load time and instance IDs observed to disappear during load. Automatic cleanup targets only the instance ID returned by this request's load call.

Evidence: `test_device_locks_are_independent`, `test_memory_preflight_uses_loaded_context_and_blocks_cap`, `test_estimator_accepts_cli_stderr_and_target_port`, `test_running_stage_visible_before_request_completes`, `test_load_reports_engine_eviction_without_unloading_itself`, `test_smart_ask_loads_and_unloads_only_owned_instance` and `test_timeout_retains_new_instance_for_inspection`; 47 self-tests passed. A real cold-load/unload was not performed.

Update: `pair_memory_plan` and both cold-load paths use the read-only LM Studio CLI estimate through the target device tunnel. A live Alfred check estimated the installed Qwen3.8 27B at 8,192 context while accounting for loaded Ornith at its actual 65,536 context and a loaded embedding model. No weights were loaded or downloaded. The CLI prints estimates to stderr, which the parser accepts. Download-plan tests cover unambiguous Hugging Face file metadata, insufficient local space and revision changes before start; the public metadata lookup did not complete from this environment, so its live success remains unverified.

Limits: native synchronous LM Studio load returns `load_time_seconds` after completion, not a percentage stream. The estimate is not measured free RAM/VRAM; the configured budget must leave OS headroom. When no budget is configured, an unavailable estimate is reported but does not block loading. LM Studio's Idle TTL and Auto-Evict are JIT server settings; Bridge neither changes them nor assumes they protect explicit loads. See https://lmstudio.ai/docs/developer/core/ttl-and-auto-evict and https://lmstudio.ai/docs/developer/rest/load.
