Попроси локальную модель проверить код, дать второе мнение или предложить другой вариант решения прямо из текущей задачи Codex. **Плагин даёт Codex инструменты для обращения к PAIR и управления моделями на настроенных устройствах.**

Набери `/pair` и выбери навык **pair** или упомяни `$pair`. После этого Astra, Sol и другие модели Codex с поддержкой инструментов смогут проверить устройства, загрузить установленную модель, задать ей ограниченный вопрос и выгрузить именно тот экземпляр, который они запустили.

> `/pair найди подходящую модель на pc, загрузи её и попроси проверить эту функцию`

Мост не скачивает модель только потому, что её имя встретилось в запросе. Сначала он читает актуальный список, поэтому отсутствующая или устаревшая запись вроде `gpt-oss-20b` будет отмечена как недоступная, а не отправлена на загрузку вслепую.

Независимый проект сообщества. Не является официальным продуктом OpenAI или NVIDIA.

## Что здесь делает MCP?

**MCP — Model Context Protocol**, протокол, через который Codex узнаёт о доступных инструментах и вызывает их. В нашем плагине небольшой MCP-сервер работает на твоём компьютере и предоставляет инструменты для просмотра, загрузки, выгрузки и опроса моделей.

У каждого участника своя роль:

| Участник | Что делает | Пример |
| --- | --- | --- |
| **Codex** | Разбирается в задаче и использует полученный ответ. | «Нужно второе мнение об этой функции». |
| **MCP-мост** | Предоставляет инструменты поиска, загрузки, выгрузки и запроса. | Проверяет устройство, загружает модель и обращается к ней. |
| **PAIR** | Маршрутизирует запрос, если устройство не задано. | Передаёт вопрос подключённому серверу моделей. |
| **Локальная модель** | Генерирует ответ. | Возвращает замечания по коду. |

**MCP подключает инструменты. PAIR маршрутизирует запросы к моделям.** Основная модель Codex продолжает вести задачу, а локальная модель выступает помощником и возвращает текст для проверки.

На картинке показан базовый маршрут через PAIR. В версии 0.4.0 мост также умеет напрямую управлять явно настроенными устройствами LM Studio.

## Как это выглядит в разговоре

> **Ты:** «Вызови `pair_list`, затем через `pair_ask` попроси модель проверить пограничные случаи этой функции».
>
> **Codex:** Получает актуальный список моделей, выбирает подходящую чат-модель и передаёт ей нужный фрагмент кода через мост.
>
> **Локальная модель:** Возвращает результаты проверки.
>
> **Codex:** Сверяет замечания с кодом и объясняет, какие изменения стоит внести.

Локальная модель получает текст, переданный инструменту. Этот мост не предоставляет ей терминал или прямой доступ к файлам.

## Быстрый старт

### 1 · Подготовь модели

Понадобятся:

- **Codex** с поддержкой каталогов плагинов.
- **[uv](https://docs.astral.sh/uv/getting-started/installation/)**, установленный и доступный через PATH.
- **Запущенный PAIR** хотя бы с одной работающей чат-моделью — для маршрутизируемых запросов.
- **LM Studio 0.4+** с включённым нативным API на каждом устройстве, которым должен управлять Codex.
- **OpenSSH** и рабочий псевдоним в SSH config для удалённого LM Studio, доступного только через loopback.

После установки uv перезапусти Codex, чтобы приложение его увидело. Проверить установку можно командой `uv --version`.

### 2 · Установи плагин

Выполни в терминале:

```sh
codex plugin marketplace add GermanMik/pair-bridge
codex plugin add pair-bridge@pair-bridge
```

Команды добавляют наш GitHub-каталог в Codex и устанавливают плагин. Это каталог сообщества, отдельный от общего каталога OpenAI. [Как устроены каталоги плагинов](https://developers.openai.com/plugins/build/plugins).

При первом запуске инструмента uv скачает зафиксированные зависимости и, если потребуется, совместимую версию Python. Следующие запуски используют кэш.

### 3 · Открой новую задачу в Codex

Сначала попробуй навык:

> `/pair покажи мои устройства и доступные модели`

Затем попроси выполнить задачу на конкретном устройстве:

> `/pair загрузи подходящую установленную чат-модель на pc, попроси проверить эту функцию, затем выгрузи запущенный тобой экземпляр`

Если всё настроено, Codex получит ответ модели и сможет использовать его в разговоре. Само наличие модели в списке ещё не означает, что она успешно загрузится.

## Что можно попросить

| Задача | Пример запроса |
| --- | --- |
| Проверить всё | «`/pair покажи настроенные устройства и каталог маршрутизатора PAIR`». |
| Проверить код на устройстве | «`/pair используй pc, чтобы найти ошибки в этом коде`». |
| Получить другой вариант | «`/pair спроси подходящую доступную модель об альтернативе и оцени ответ`». |
| Сравнить устройства | «`/pair спроси одну модель на mac и одну на pc, затем сравни ответы`». |

На разных компьютерах названия моделей различаются. Перед выбором `/pair` проверяет актуальный каталог.

## Как указать адрес PAIR

По умолчанию используется **`http://127.0.0.1:1234/v1`** — адрес прокси PAIR в проверенной конфигурации. Если у тебя другой порт, посмотри адрес в интерфейсе PAIR.

Для изменения адреса создай файл **`.pair-bridge.json` в домашней папке**:

```json
{
  "base_url": "http://127.0.0.1:1234/v1"
}
```

| Система | Расположение файла |
| --- | --- |
| macOS / Linux | `~/.pair-bridge.json` |
| Windows | `%USERPROFILE%\.pair-bridge.json` |

Указывай адрес **маршрутизатора PAIR**. Если указать отдельный сервер LM Studio, будут доступны модели только этого сервера. `127.0.0.1` означает компьютер, на котором запущен мост.

<details>
<summary><strong>Переменные окружения и авторизация</strong></summary>

Можно задать `PAIR_BASE_URL` в окружении, которое наследует Codex. Эта переменная имеет приоритет над файлом настроек.

Если сервер требует bearer-токен, задай `PAIR_API_KEY` в том же окружении. Не вставляй секреты в адрес сервера и не публикуй их в репозитории.

</details>

## Настройка управляемых устройств

Добавь адреса нативного API LM Studio в тот же файл настроек. Они указываются отдельно от прокси PAIR:

```json
{
  "base_url": "http://127.0.0.1:1234/v1",
  "devices": [
    {"id": "mac", "engine": "lmstudio", "base_url": "http://127.0.0.1:1235"},
    {"id": "pc", "engine": "lmstudio", "base_url": "http://127.0.0.1:1235", "ssh_host": "my-pc"}
  ]
}
```

Укажи реальный адрес нативного API каждой установки LM Studio; порты выше приведены только для примера. `ssh_host` должен быть существующим псевдонимом OpenSSH config. Мост создаёт временный туннель только на loopback с проверкой ключа сервера, не выполняет удалённые команды и закрывает туннель после запроса. Поддерживается и прямой HTTPS-адрес.

Для каждого устройства можно задать положительный лимит `max_loaded_bytes`. Bridge отклоняет холодную загрузку, если сумма размеров уже загруженных весов и новой модели превышает лимит; KV-кеш и накладные расходы сюда не входят. Запросы ждут до 30 секунд в очереди своего устройства; `/pair diagnose` показывает этапы очереди, загрузки и ответа. Результат загрузки сообщает время из LM Studio и экземпляры, исчезнувшие во время загрузки. Bridge автоматически выгружает только экземпляр, который загрузил сам. [Idle TTL и Auto-Evict LM Studio](https://lmstudio.ai/docs/developer/core/ttl-and-auto-evict) зависят от настроек JIT сервера; Bridge их не меняет.

Предварительная оценка памяти запланирована, но ещё не реализована: `lms load --estimate-only --context-length N` оценивает память для установленной модели без её загрузки. Контекст существенно влияет на результат: на Alfred для Qwen3.8 27B получилось 19,24 GiB при 8192 токенах и 26,03 GiB при 65 536. Для уже загруженного экземпляра API сообщает фактический `loaded_instances[].config.context_length`; `max_context_length` — лишь поддерживаемый предел. Для незагруженной модели Bridge должен явно выбрать планируемый контекст. `size_bytes` — размер весов, а не полное потребление RAM/VRAM. [CLI LM Studio](https://lmstudio.ai/docs/cli/local-models/load), [инвентарь моделей](https://lmstudio.ai/docs/developer/rest/list).

Устройства добавляются явно. Обнаружение участников PAIR не даёт доступа к управлению их моделями. Управление Ollama, удаление весов, установка движков и администрирование кластера PAIR пока не реализованы. Скачивание выделено в отдельный инструмент и не запускается обычным запросом к модели.

Если устройство требует авторизации, укажи в `api_key_env` имя переменной окружения с токеном и передай её MCP-процессу через `env_vars` в `.mcp.json`. Не сохраняй токены в Git и не вставляй их в запросы.

## Какие данные остаются локальными?

Мост работает на твоём компьютере и отправляет запросы **на настроенный тобой PAIR**. PAIR может передавать их подключённым серверам моделей. Автор плагина не получает запросы через этот плагин.

**Вся переписка с Codex при этом не обязательно локальная.** Ответы моделей возвращаются в Codex и обрабатываются согласно твоим настройкам Codex/OpenAI. PAIR и серверы моделей также могут сохранять собственные журналы. [Подробнее о данных](PRIVACY.md).

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Инструменты не появились | Открой новую задачу. Проверь, что плагин включён, а uv доступен в PATH приложения Codex. |
| Нет соединения с PAIR | Запусти PAIR и сверь адрес с файлом настроек. |
| Настроенное устройство недоступно | Проверь нативный API и порт LM Studio, затем прямое HTTPS- или SSH-подключение. |
| Модель есть в списке, но не отвечает | Открой сведения о запросе в PAIR и журнал сервера моделей. Список моделей не является проверкой их работоспособности. |
| Указанная модель не установлена | Запусти инвентаризацию через `/pair` и выбери точный ключ установленной модели; мост не скачивает отсутствующие веса. |
| HTTP 400 или 500 | Проверь точное имя модели, её загрузку, доступную память и ошибки сервера. |
| Другой запрос уже выполняется | Дождись завершения текущего вызова через мост. |
| Истекло время ожидания | Перед повтором проверь PAIR: предыдущая генерация могла продолжиться. |
| Нет итогового текста | Модель могла потратить лимит вывода на рассуждения. Проверь результат перед увеличением лимита. |

## Slash-команда и MCP-инструменты

`/pair` включает навык, который объясняет Codex порядок безопасной работы с моделями. Имена ниже — MCP-инструменты этого навыка, а не команды терминала.

Без `device` инструменты `pair_list` и `pair_ask` работают через маршрутизатор PAIR. С параметром `device` они обращаются напрямую к настроенному LM Studio. Для прямого запроса должен быть загружен ровно один экземпляр выбранного ключа модели.

**`pair_ask`** — принимает обязательные `model` (точное имя из `pair_list`) и `prompt` (вопрос). Необязательный `max_tokens` по умолчанию равен `2048`.

Пример параметров `pair_ask` — замени имя модели:

```json
{
  "model": "<точное имя из pair_list>",
  "prompt": "Проверь пограничные случаи этой функции: ...",
  "max_tokens": 2048
}
```

## Справочник инструментов

| Инструмент | Что принимает | Что возвращает |
| --- | --- | --- |
| `pair_devices` | Без параметров. | Доступность, установленные и загруженные модели на всех настроенных устройствах. |
| `pair_list` | Необязательный `device`. | Каталог PAIR или нативный список моделей одного устройства. |
| `pair_load` | `device`, `model`, необязательный `context_length`. | Использованный или новый экземпляр и его точный идентификатор. |
| `pair_unload` | `device`, `instance_id`. | Подтверждение, что один точный экземпляр больше не наблюдается. |
| `pair_ask` | `model`, `prompt`, необязательные `device`, `max_tokens`. | Ответ, модель, статус завершения, время и сведения о токенах, если доступны. |
| `pair_smart_ask` | `prompt`; необязательные `model`, `device`, `task_hint` (`general`, `code`, `fast`, `long_context`, `analysis`), `context_length`, `max_tokens`, `unload_after`. | Выбирает установленную модель по живому инвентарю, загружает при необходимости, задаёт один вопрос и сообщает результат очистки. |
| `pair_compare` | Вопрос и две точные пары «устройство/модель». | Два последовательных ответа, общие и спорные замечания; Codex проверяет их по исходному коду. |
| `pair_diagnose` | Нет. | Состояние PAIR и устройств, недавние этапы запросов, длительности и безопасные причины ошибок без текста запросов и токенов. |
| `pair_download_plan` / `pair_download` / `pair_download_status` | Точная модель, проверенные оценка размера и путь, одноразовый ID плана, повторное `confirm_model`; ID задания. | План показывает источник и введённые пользователем размер и путь до запуска. LM Studio сообщает фактический размер лишь после начала загрузки; проверь свободное место и настройки хранения. |
| `pair_decide` / `pair_score` | Состояние, варианты Choice или упорядоченные уровни Score, `allow_external=true`. | Необязательная типизированная оценка облачной модели TypeSafe AI Jev; нужен `TYPESAFE_API_KEY`. |

Умный путь требует хотя бы одно настроенное и доступное устройство LM Studio. Он сохраняет уже загруженные экземпляры. После успешного ответа экземпляр, загруженный этим вызовом, по умолчанию выгружается; после ошибки или тайм-аута остаётся для проверки. Мост не видит работу других приложений с LM Studio: если модель общая, задай `unload_after=false`.

Для Oh My Pi добавлены собственные `/pair` и навык; см. [инструкцию подключения OMP](docs/OMP.md). Jev — отдельный внешний сервис решений, а не локальная чат-модель; данные отправляются ему только при явном `allow_external=true`.

<details>
<summary><strong>Лимиты и поведение запросов</strong></summary>

- Перед обращением к модели список обновляется; нужно точное имя.
- Предполагаемые embedding- и draft-модели отсекаются для чат-запросов. Тип определяется по имени.
- Загрузка, выгрузка и генерация ставятся в очередь отдельно для каждого настроенного устройства между процессами моста одного пользователя. Запросы к маршрутизатору используют отдельную блокировку, поскольку конечный узел неизвестен. Другие приложения этим ограничением не охвачены.
- Нет автоматических повторов, подмены модели или скачивания весов при запросе. Сервер может загрузить уже установленную модель и занять GPU/RAM.
- Лимит вывода по умолчанию — 2 048 токенов; диапазон — 32–8 192. Входной текст — до 48 000 символов. Ограничения контекста самой модели также действуют.
- Ожидание ответа — до 180 секунд. Отмена или тайм-аут не гарантируют остановку генерации на сервере.
- Пустой итоговый ответ считается ошибкой. Ответ, остановленный лимитом токенов, помечается как обрезанный.
- Выгрузка действует на точный экземпляр LM Studio и может помешать другому приложению, которое его использует. Навык отслеживает загрузки текущей задачи и избегает выгрузки чужих экземпляров.
- Мост не меняет постоянные настройки движков и не исправляет каталоги. Явная загрузка может задать размер контекста.

</details>

## Переход с `codex-pair-bridge`

Новое имя marketplace и плагина — `pair-bridge`. Старый файл `~/.codex-pair-bridge.json` продолжает работать; новый `~/.pair-bridge.json` имеет приоритет. Каталог локального журнала сохраняет старое имя ради истории. Для установленной старой версии:

```sh
codex plugin remove codex-pair-bridge@codex-pair-bridge
codex plugin marketplace remove codex-pair-bridge
codex plugin marketplace add GermanMik/pair-bridge
codex plugin add pair-bridge@pair-bridge
```

## Обновление предыдущей версии

```sh
codex plugin marketplace upgrade pair-bridge
codex plugin add pair-bridge@pair-bridge
```

После обновления открой новую задачу, чтобы Codex увидел навык `/pair` и текущие MCP-инструменты. Версия 0.5.0 добавила инвентаризацию устройств и управление загрузкой; новые умные инструменты доступны пока в рабочей копии репозитория.

## Разработчикам

```sh
cd plugins/pair-bridge
uv run --locked --script ./scripts/server.py --self-test
```

Автоматические тесты проверяют MCP, параметры, настройки, планирование SSH-туннеля, инвентаризацию, загрузку и выгрузку, ошибки, тайм-ауты, блокировку операций и разбор ответов. CI запускается на **macOS, Windows и Linux**. Ранее маршрутизируемые и прямые запросы проверялись на macOS и удалённом Windows-узле; новые сценарии требуют отдельной проверки на реальных устройствах.

Зависимости зафиксированы в `scripts/server.py.lock`. Для обновления используй `uv lock --script scripts/server.py`, затем запусти тесты.
