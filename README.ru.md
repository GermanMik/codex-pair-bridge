Попроси локальную модель проверить код, дать второе мнение или предложить другой вариант решения прямо из текущей задачи Codex. **Плагин даёт Codex два инструмента для обращения к твоему PAIR.**

Независимый проект сообщества. Не является официальным продуктом OpenAI или NVIDIA.

## Что здесь делает MCP?

**MCP — Model Context Protocol**, протокол, через который Codex узнаёт о доступных инструментах и вызывает их. В нашем плагине небольшой MCP-сервер работает на твоём компьютере и предоставляет два действия: **показать модели** и **задать вопрос модели**.

У каждого участника своя роль:

| Участник | Что делает | Пример |
| --- | --- | --- |
| **Codex** | Разбирается в задаче и использует полученный ответ. | «Нужно второе мнение об этой функции». |
| **MCP-мост** | Предоставляет инструменты для обращения к моделям. | Принимает имя модели и текст вопроса. |
| **PAIR** | Направляет запрос выбранной модели. | Передаёт вопрос подключённому серверу моделей. |
| **Локальная модель** | Генерирует ответ. | Возвращает замечания по коду. |

**MCP подключает инструменты. PAIR маршрутизирует запросы к моделям.** Основная модель Codex продолжает вести задачу, а локальная модель выступает помощником и возвращает текст для проверки.

На картинке: **Plans the task** — ведёт задачу; **Exposes two tools** — предоставляет два инструмента; **Routes the request** — направляет запрос; **Model answer returns to Codex** — ответ возвращается в Codex.

## Как это выглядит в разговоре

> **Ты:** «Вызови `pair_list`, затем через `pair_ask` попроси модель проверить пограничные случаи этой функции».
>
> **Codex:** Получает актуальный список моделей, выбирает подходящую чат-модель и передаёт ей нужный фрагмент кода через мост.
>
> **Локальная модель:** Возвращает результаты проверки.
>
> **Codex:** Сверяет замечания с кодом и объясняет, какие изменения стоит внести.

Локальная модель получает текст, переданный инструменту. Этот мост не предоставляет ей терминал или прямой доступ к файлам.

## Быстрый старт

### 1 · Подготовь модели

Понадобятся:

- **Codex** с поддержкой каталогов плагинов.
- **[uv](https://docs.astral.sh/uv/getting-started/installation/)**, установленный и доступный через PATH.
- **Запущенный PAIR**, подключённый к серверу хотя бы с одной работающей чат-моделью.

После установки uv перезапусти Codex, чтобы приложение его увидело. Проверить установку можно командой `uv --version`.

### 2 · Установи плагин

Выполни в терминале:

```sh
codex plugin marketplace add GermanMik/codex-pair-bridge
codex plugin add codex-pair-bridge@codex-pair-bridge
```

Команды добавляют наш GitHub-каталог в Codex и устанавливают плагин. Это каталог сообщества, отдельный от общего каталога OpenAI. [Как устроены каталоги плагинов](https://developers.openai.com/plugins/build/plugins).

При первом запуске инструмента uv скачает зафиксированные зависимости и, если потребуется, совместимую версию Python. Следующие запуски используют кэш.

### 3 · Открой новую задачу в Codex

Напиши:

> Вызови `pair_list` и покажи доступные модели.

Затем используй **точное имя модели** из полученного списка:

> Вызови `pair_ask` для `<имя модели>`: объясни эту функцию и проверь пограничные случаи.

Если всё настроено, Codex получит ответ модели и сможет использовать его в разговоре. Само наличие модели в списке ещё не означает, что она успешно загрузится.

## Что можно попросить

| Задача | Пример запроса |
| --- | --- |
| Узнать доступные модели | «Вызови `pair_list` и покажи модели». |
| Проверить код | «Вызови `pair_ask` для `<имя модели>`: найди ошибки в этом коде». |
| Получить другой вариант | «Через `pair_ask` спроси модель из `pair_list` об альтернативе и оцени её ответ». |
| Сравнить ответы | «Вызови `pair_list`, затем `pair_ask` для двух чат-моделей по очереди и сравни ответы». |

Замени `<имя модели>` на имя из актуального каталога. На разных компьютерах названия могут отличаться.

## Как указать адрес PAIR

По умолчанию используется **`http://127.0.0.1:1234/v1`** — адрес прокси PAIR в проверенной конфигурации. Если у тебя другой порт, посмотри адрес в интерфейсе PAIR.

Для изменения адреса создай файл **`.codex-pair-bridge.json` в домашней папке**:

```json
{
  "base_url": "http://127.0.0.1:1234/v1"
}
```

| Система | Расположение файла |
| --- | --- |
| macOS / Linux | `~/.codex-pair-bridge.json` |
| Windows | `%USERPROFILE%\.codex-pair-bridge.json` |

Указывай адрес **маршрутизатора PAIR**. Если указать отдельный сервер LM Studio, будут доступны модели только этого сервера. `127.0.0.1` означает компьютер, на котором запущен мост.

<details>
<summary><strong>Переменные окружения и авторизация</strong></summary>

Можно задать `PAIR_BASE_URL` в окружении, которое наследует Codex. Эта переменная имеет приоритет над файлом настроек.

Если сервер требует bearer-токен, задай `PAIR_API_KEY` в том же окружении. Не вставляй секреты в адрес сервера и не публикуй их в репозитории.

</details>

## Какие данные остаются локальными?

Мост работает на твоём компьютере и отправляет запросы **на настроенный тобой PAIR**. PAIR может передавать их подключённым серверам моделей. Автор плагина не получает запросы через этот плагин.

**Вся переписка с Codex при этом не обязательно локальная.** Ответы моделей возвращаются в Codex и обрабатываются согласно твоим настройкам Codex/OpenAI. PAIR и серверы моделей также могут сохранять собственные журналы. [Подробнее о данных](PRIVACY.md).

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Инструменты не появились | Открой новую задачу. Проверь, что плагин включён, а uv доступен в PATH приложения Codex. |
| Нет соединения с PAIR | Запусти PAIR и сверь адрес с файлом настроек. |
| Модель есть в списке, но не отвечает | Открой сведения о запросе в PAIR и журнал сервера моделей. Список моделей не является проверкой их работоспособности. |
| HTTP 400 или 500 | Проверь точное имя модели, её загрузку, доступную память и ошибки сервера. |
| Другой запрос уже выполняется | Дождись завершения текущего вызова через мост. |
| Истекло время ожидания | Перед повтором проверь PAIR: предыдущая генерация могла продолжиться. |
| Нет итогового текста | Модель могла потратить лимит вывода на рассуждения. Проверь результат перед увеличением лимита. |

## Две команды

Это **имена MCP-инструментов внутри Codex**, а не команды терминала или slash-команды. Укажи имя в сообщении — Codex передаст нужные параметры инструменту.

**`pair_list`** — вызывается без параметров и возвращает актуальный каталог.

**`pair_ask`** — принимает обязательные `model` (точное имя из `pair_list`) и `prompt` (вопрос). Необязательный `max_tokens` по умолчанию равен `2048`.

Пример параметров `pair_ask` — замени имя модели:

```json
{
  "model": "<точное имя из pair_list>",
  "prompt": "Проверь пограничные случаи этой функции: ...",
  "max_tokens": 2048
}
```

## Справочник инструментов

| Инструмент | Что принимает | Что возвращает |
| --- | --- | --- |
| `pair_list` | Без параметров. | Актуальные имена моделей и предполагаемые типы. |
| `pair_ask` | `model`, `prompt`, необязательный `max_tokens`. | Ответ, имя модели в ответе сервера, статус завершения, время и сведения о токенах, если сервер их передал. |

<details>
<summary><strong>Лимиты и поведение запросов</strong></summary>

- Перед обращением к модели список обновляется; нужно точное имя.
- Предполагаемые embedding- и draft-модели отсекаются для чат-запросов. Тип определяется по имени.
- Между процессами этого моста для одного пользователя допускается одна генерация одновременно. Другие приложения этим ограничением не охвачены.
- Нет автоматических повторов, подмены модели или скачивания моделей. Сервер может загрузить уже установленную модель и занять GPU/RAM.
- Лимит вывода по умолчанию — 2 048 токенов; диапазон — 32–8 192. Входной текст — до 48 000 символов. Ограничения контекста самой модели также действуют.
- Ожидание ответа — до 180 секунд. Отмена или тайм-аут не гарантируют остановку генерации на сервере.
- Пустой итоговый ответ считается ошибкой. Ответ, остановленный лимитом токенов, помечается как обрезанный.
- Мост не меняет настройки движков и не исправляет каталоги моделей.

</details>

## Обновление предыдущей версии

```sh
codex plugin marketplace upgrade codex-pair-bridge
codex plugin add codex-pair-bridge@codex-pair-bridge
```

После обновления открой новую задачу. В версии 0.3.0 инструменты получили короткие имена **`pair_list`** и **`pair_ask`**. Если старые имена были в сохранённых запросах, замени их.

## Разработчикам

```sh
cd plugins/codex-pair-bridge
uv run --locked --script ./scripts/server.py --self-test
```

Девять тестов проверяют MCP, параметры, настройки, ошибки, тайм-ауты, блокировку запросов и разбор ответов. Они прошли на **macOS, Windows и Linux**. Проверены также реальные запросы из macOS к локальной Ornith и Qwen на Windows-узле; это не гарантирует совместимость с любой моделью и сервером.

Зависимости зафиксированы в `scripts/server.py.lock`. Для обновления используй `uv lock --script scripts/server.py`, затем запусти тесты.
